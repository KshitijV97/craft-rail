# Diagram guide

Keep Mermaid in a fenced Markdown block or `.mmd` file. Start with a recognized declaration (`flowchart`, `graph`, `sequenceDiagram`, `classDiagram`, `stateDiagram`, `erDiagram`, `journey`, `mindmap`, `timeline`, `C4Context`, `C4Container`, or `C4Component`), add a title and explanation, and state scope/abstraction/last-reviewed date nearby. Reuse names across views. A diagram should communicate a boundary, relationship, flow, or lifecycle rather than decorate prose.

Commit text source, never only a rendered image. GitHub renders common Mermaid diagrams; local editors may provide preview extensions. Rendering is optional and is not performed by CraftRail's validator. See templates and the illustrative sequence and data-flow examples.
