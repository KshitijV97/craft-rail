# Worked example: account recovery request

This fictional example demonstrates artifact flow, not a safe production account recovery architecture.

1. `specs/000-example-feature/spec.md` defines `FR-001` and `AC-001`/`AC-002` in a bounded scope.
2. The [plan](../../specs/000-example-feature/plan.md) points out security work that remains unspecified and includes sequence/data-flow views.
3. [Tasks](../../specs/000-example-feature/tasks.md) link work to requirements and verification IDs.
4. The [verification matrix](../../specs/000-example-feature/verification.md) connects each criterion to evidence, and clearly says no application test was run.

For a real feature, review/approve the spec, create a real design and tests, replace illustrative statuses, and converge the docs after implementation. The sample deliberately calls out missing token lifecycle, abuse controls, privacy, and threat analysis.
